# 关键坑与经验 —— 机顶盒变「去广告 DNS 盒子」

## 1. ⭐ 老盒子子系统 UDP 被封锁 → DNS 上游必须 TCP
B860AV 子系统里**对外 UDP 不通**（历史坑：DNS 需 DNS-over-TCP 桥）。
AdGuard Home 默认上游是 **UDP:53** → 收得到查询但**转发不出去 → nslookup 超时**。
→ 上游改成 **`tcp://223.5.5.5` / `tcp://119.29.29.29` / `tcp://114.114.114.114`** 即通。

## 2. ⭐ AdGuard 二进制只有 https，过滤列表默认也是 https
盒子子系统**只通 HTTP/80** → 两样都得处理：
- 二进制：在**电脑上（有 https）**下 `AdGuardHome_linux_arm64.tar.gz`，再传进盒子。
- 过滤列表：用 **http** 列表（`pgl.yoyo.org`、`someonewhocares.org`）；AdGuard 默认的 https 列表会 0 条。

## 3. 首次配置免网页向导
AdGuard 首次运行只开 :3000 的"设置向导"页。无头环境可**直接调 API**：
`POST /control/install/configure` 提交 `{web:{ip,port}, dns:{ip,port}, username, password}` → 一步配好。

## 4. 端口 53 需要 root
chroot 内是 root → 可绑 53。绑前先确认没有被别的服务占用。

## 5. 盒子 chroot 可能没有 curl
用 `python3`（stdlib urllib）调 API；或 `wget`。本项目脚本都用 python3。

## 6. 拦截的边界
DNS 层拦不到：**硬编码 IP**、**DoH/DoT**、视频前贴片/YouTube（前端广告）。
→ 是"大幅减少"，非 100%。

## 7. 单点风险
盒子当全家 DNS → 它挂/重启时解析会断。路由器设**备用 DNS**。

## 8. 传输大文件慢
从 GitHub 直连下载 ~50KB/s，官方 `static.adtidy.org` 更快（~100KB/s）。大文件下载耐心/换镜像。

## 9. 进程自启幂等
`pgrep -f "[A]dGuardHome" || ( ... )` —— 注意 `[A]` 锚定，避免 `pkill/pgrep -f` 误伤执行命令的 shell。
